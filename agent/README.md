# SX Monitor — Агент (Windows)

Легкий клієнт для моніторингу Windows-серверів 1С. Збирає метрики через
`collectors/`, шле їх на центральний сервер (`POST /api/metrics`) і виконує
команди з черги (block_ip / kick_session / restart_service / reboot).

Аналіз метрик, дедуплікація алертів і Telegram — на центральному сервері.

## Встановлення (на Windows-сервері, PowerShell від адміністратора)

```powershell
irm "https://raw.githubusercontent.com/vskoropada-rgb/sx-monitor-server/main/agent/install.ps1" | iex
```

Інсталятор завантажить файли і запустить `manage.ps1` (інтерактивне меню).

## Меню manage.ps1

| Пункт | Дія |
|-------|-----|
| 0 | Підготовка сервера (Python, ExecutionPolicy) |
| 1 | Встановити / Оновити (створює Task Scheduler завдання для `agent.py`) |
| 2 | Налаштувати сервер: назва компанії, SERVER_ID, Telegram-топік, **API_URL**, диски, сервіси |
| 5 | Переглянути налаштування |
| 6 | Статус завдань |
| 7 | Перезапустити моніторинг |
| 8 | Видалити |
| **R** | **Реєстрація агента на центральному сервері** (`register_agent.py`) |
| U | Оновлення з GitHub |

## Порядок налаштування нового сервера

1. **0** — підготувати сервер (Python)
2. **1** — встановити залежності, створити завдання
3. **2** — заповнити: COMPANY_NAME, SERVER_ID, TG_TOPIC_ID, **API_URL** (адреса центрального сервера)
4. **R** — зареєструвати агента (введи `REGISTER_SECRET` з `.env` центрального сервера)
5. **7** — запустити моніторинг

## Конфіг (.env)

Ключові поля:
```env
SERVER_ID=company_a                 # унікальний slug
COMPANY_NAME=Компанія А             # людська назва (в заголовках алертів)
API_URL=http://<адреса-сервера>     # центральний сервер
API_KEY=                            # генерується при реєстрації (зашифрований DPAPI)
TG_TOPIC_ID=12345                   # тема компанії в Telegram-групі
```

Решта (пороги дисків/CPU/RAM, бекапи, безпека) — див. `.env.example`.
